## Verified contracts and implementation contradictions

- Search must not scale. Current `HeroSection.tsx` uses `hover:scale-[1.015]` and a 2px blue outer shadow; this contradicts the exact `49:756 -> 49:731` contract.
- Quick access must not scale. Current `ShortcutMenu.tsx` uses `scale-[1.025]`, uses 200ms instead of 300ms, and uses a solid blue outline/shadow instead of a 4px gradient stroke plus active y=-4 positioning.
- Search default border is currently white in the React class, while Figma specifies approximately `#E5E7EB`; the current hover implementation also changes geometry.
- Navbar currently uses 150ms color/rotation transitions and rotates the chevron with a CSS assumption; prototype reactions are 300ms Smart Animate and require live-instance visual inspection.
- `SchoolAdvantages.tsx`, `HomepageSections.tsx`, and related CSS contain generic hover shadows/transitions, but they do not prove destination-variant parity; status remains PARTIAL until destination states are mapped in implementation.
- `final-controls.css` and reduced-motion rules may disable or alter intended transitions; implementation agent must verify them against this matrix.
- Existing working-tree changes were preserved; no modified React/CSS file was reverted or edited by this audit.
